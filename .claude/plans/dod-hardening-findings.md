(d) The review checklist / spec template requires a matrix row for any new tool whose behaviour depends on visibility.

**Cost.** Runtime about 1-2 min added to contract_green. Each role/user/key create and invalidate is sub-second, plus about 2 tool calls per row per key. Maintenance: one parametrize row per new privilege-dependent tool. Infra: none, since it uses the same seeded stack and the Kibana internal security routes the suite already calls (test_gateway_contract.py:3324-3337). It runs in CI's contract matrix too.

## privilege-2 [low] — Copy/share/overwrite target validation reports an existing-but-invisible space as 'not found, create it' (the fix it names is wrong), and no test uses a key that cannot view a target space

**Evidence.** gateway.py:3339-3348 _require_spaces builds `known` from self._client.spaces.get_all(). kibana-py documents get_all as returning spaces 'that the authenticated user has access to view' (.venv/.../kibana/_async/client/spaces.py:205-209), and 24bde1a confirmed live that a restricted key's listing shows only 'default'. A miss raises missing_spaces_message (core/space_sharing.py:34-42): '... not found ... create the space with create_space first'. By contrast, connect() validates a `space` via spaces.get, which answers 403 -> KibanaAuthError '... able to read spaces' (gateway.py:1470-1484). The only restricted copy test (test_gateway_contract.py:3344) grants `read` in every target space, so every target is visible and this branch never runs with a restricted key. The list_spaces description still says 'List all Kibana spaces' (platform_admin/toolbox.py:148), which 24bde1a showed is false under a restricted key. Not live-probed here (read-only task); the code path is clear-cut.

**Failure Scenario.** An HTTP caller's key grants `all` in 'default' and 'marketing', and space 'ops' exists. The model calls copy_saved_objects_to_spaces(target_spaces=['ops']). The tool answers "space 'ops' not found ... create the space with create_space first". The model calls create_space('ops'), which fails 409/403, or worse, picks a near-miss id and copies there. This breaks the house rule that error text must name the fix, and no gate tier can see it.

**Proposed Change.** Add a privilege-matrix row (finding 1): a key that can view only 'default' copies into an existing throwaway space. Assert the refusal names the key's privileges (a new key from a user whose role grants the space; both ways to send it), not create_space. Code fix: on a miss, call spaces.get(id) for each missing id. A 404 means genuinely missing; a 403 means not visible to this key. Amend the list_spaces description to say 'spaces this key can view'. Reconcile D49 and the platform-admin spec in the same change.

**Cost.** One contract test of about 5 s. The code change is a few lines plus a unit test. No infra.

**Verifier.** Code path confirmed. gateway.py:3339-3348 _require_spaces builds `known` from spaces.get_all(), and a miss raises missing_spaces_message (core/space_sharing.py:34-42), which tells the model to 'create the space with create_space first'. connect() instead reports 403 as an auth error (gateway.py:1470-1484). The map is inconsistent within one toolbox: D51 gave update_agent_tags and request_agent_diagnostics an edge to list_agents (tool_lists.py:125-127), but get_agent, reassign_agent and unenroll_agent have none. Selections made with toolboxes alone are never checked (docs/configuration.md:233), although cross-toolbox edges exist: create_synthetic_private_location (observability) -> list_agent_policies (fleet).

**Failure Scenario.** Scenario 1: an operator sets KIBANA_MCP_TOOLS=get_case,update_case,add_case_comment, or a narrow fleet list without list_agents. No coherence warning is logged because no edge exists. The model receives tools whose ids it cannot discover, and get_case's description does not say where ids come from, so it guesses or passes a title. Scenario 2: KIBANA_MCP_TOOLBOXES=observability at write publishes create_synthetic_private_location without its only id source. Every test passes and the gate reads GO; the usability defect shows up only in front of a user.

**Proposed Change.** Add a completeness test to test_tool_lists.py. Every published tool with a required id-like parameter (pattern *_id, *_ids, id, list_id, handle) must have a DEPENDENCIES edge or sit on an explicit exemption tuple with a reason, for user-chosen identifiers such as create_space.id or resolve_short_url.slug. Its description must also name at least one of its source tools by name. Add a parametrized test that runs the existing coherence check over every single toolbox at every tier and every shipped profile, asserting no missing tool or matching a short, reviewed list of accepted cross-toolbox gaps.

**Cost.** Runtime: about 1 s in unit_green. Maintenance: a one-time triage of about 35 entries (add an edge and a one-sentence pointer, or an exemption), then one line per new id-taking tool. No infra.

**Verifier.** Verified. test_tool_lists.py checks edge soundness only. get_case's signature takes case_id, and the DEPENDENCIES map has no find_cases edge. update_agent_tags and request_agent_diagnostics have list_agents edges, while get_agent, reassign_agent and unenroll_agent have none (tool_lists.py:125-128). Note that by D41's own rule (an edge only when the description or error sends the model to B), a missing pointer is not a rule violation. The gap is that the rule cannot detect an id with no stated source. A completeness test with an exemption tuple is cheap. It is a usability nicety, not a correctness gate. Absorbs docs-3.
