mcp-for-kibana

An MCP server for Kibana: an LLM works with Kibana through 143 purpose-built tools in 10 toolboxes you enable per deployment, instead of about 610 raw REST endpoints.

  • Kibana 9.4 and 9.5

Measured: MCP against Direct API

Claude Code did one long Kibana job 600 times, with three models, either through this server's tools (MCP) or by calling Kibana's REST API itself from the shell with the pinned API reference (Direct API). Every run passed every check. Median per run, MCP ÷ Direct API; below 1, MCP is cheaper or faster.

What it does

  • Composable toolboxes. Enable only the toolboxes a deployment needs with KIBANA_MCP_TOOLBOXES; the default is dashboards,data-management. Small local models get a small surface, big models can get more.
  • Tiered write safety. Every tool is classified read, write or destructive (68 / 45 / 30). KIBANA_MCP_TIER caps the tier (default write); a tool above the cap is never shown to the model, not merely refused when called.
  • Dashboards from a declarative spec. The dashboards toolbox turns a simple spec into Kibana Lens visualizations and dashboards through Kibana's Dashboards and Visualizations APIs. Elastic marks those APIs Technical Preview, so their shapes may still change between Kibana releases.
  • Your key, your permissions. Stdio for a single local user, or streamable HTTP in a container for several. Each request carries the caller's own Kibana API key, so Kibana's access control and audit log stay per user.
  • Basic license. Every tool works on a Basic (free) Kibana license; features that need a paid Elastic subscription are out of scope.

Install

From PyPI, with a Kibana API key:

export KIBANA_URL=https://your-kibana.example.com
export KIBANA_API_KEY=<your Kibana API key>
uvx mcp-for-kibana
# or: pip install mcp-for-kibana

It runs on stdio by default. Connecting Claude Code, LM Studio or an HTTP client, and a disposable local Kibana with sample data: user guide, configuration, deployment.
